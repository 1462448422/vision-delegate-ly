# @deepseek-ai/dsh-vision-delegate

[English](README.md) | 中文

面向纯文本模型路由的视觉委派。当所选模型不支持图片输入时，由图像模型（显式配置，或自动发现注册列表中第一个声明 `image` 输入的模型）在消息进入本轮之前描述用户附带的图片；识别文字以独立的插件来源上下文消息紧随用户消息记录，图片块保留在日志里，转录继续正常显示原图。

## 组合配置

```yaml
- id: vision-delegate
  name: '@deepseek-ai/dsh-vision-delegate'
```

所有配置项均可选，默认开启并自动发现视觉模型。

```yaml
- id: vision-delegate
  name: '@deepseek-ai/dsh-vision-delegate'
  config:
    enabled: true
    provider: acme-gateway        # 显式指定视觉路由（与 model 成对出现）
    model: qwen3.7-plus
    prompt: '...'                 # 识别提示词（系统提示）
    maxOutputTokens: 1024
```

## 行为

- **识别（`agent/pre-step`）**——含图片的消息，若其路由模型无法看图，在写入日志前为每条消息发起一次识别调用：把该消息的全部图片块连同配置的系统提示发给视觉模型，回复成为紧随其后的独立 `[attached image recognized by vision model "..."]` 上下文消息（插件来源、`notice` 形态），模型读取描述文字，而用户气泡只保留图片与原文。识别失败会抛错，整个回合显式失败，而不是静默忽略图片继续。
- **请求过滤（`llm/stream`）**——任何路由到不支持图片的模型的请求，其图片块会被替换为 `[image attachment <id>]` 占位文字，相邻的已记录识别文字保持不变。无图片的请求与支持图片的路由原样通过。
- **不可用时保持惰性**——自动发现找不到图像模型时，准入逻辑维持原有拒绝行为，请求不做任何改写；显式配置的路由未声明图片输入时，在首次准入检查处即报错，而非等到第一张图片。
- **原生视觉会话不受影响**——所选模型本身支持图片时不做任何委派，模型直接读图。

## 模型体验

### 识别调用

#### 模型看到什么

视觉模型只收到附带的图片块与识别系统提示，不含会话历史、工具或工作区上下文。

#### Token 影响

每条含图消息产生一次视觉路由上的辅助调用，输出受 `maxOutputTokens`（默认 1024）约束。识别文字随独立的上下文消息保留，在后续每次请求中随历史重发，直到被压缩覆盖。

#### KV 缓存影响

主路由请求结构不变，上下文消息紧随用户消息；辅助识别调用不复用会话缓存。

## 已知限制与后续工作

- **切换模型后的陈旧请求头窗口**——委派依据最近一次记录的请求头配置（回退到 Agent 选项）。刚从视觉模型切走后发出的第一条消息，图片可能绕过识别；请求过滤仍会剔除图片块，重发图片会再次委派。刚切到视觉模型后的第一条消息则可能出现一次冗余委派。
- **按消息粒度识别**——一条消息里的多张图片由一次识别调用统一描述，描述文字不逐图归因。
- **暂无 GUI 配置**——插件目前仅通过 cordis.yml 组合，设置页还没有它的卡片；`read_image` 工具保持自身严格的图片路由门槛。
- **无独立质检**——识别回复原样记录，不校验其是否真正描述了图片。
